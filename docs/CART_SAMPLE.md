# 장바구니 연동 초안

관련: BE [장바구니 설계 #94](https://github.com/adapterz/wku-iksan-store-BE/issues/94).

`/cart-sample`에서 BE `feat/cart-order-groups`와 연동합니다. 운영에 적용하지 않은 독립 기능 검증 화면이며, 디자인 확정본이 아닙니다. 기존 홈/상품/선물함 파일은 수정하지 않았습니다.

- 기존 로그인 세션을 사용합니다. 수신자는 기존 닉네임 검색 API로 확인합니다.
- 상품 담기, 수량 변경, 선택·삭제, 본인/타인 선물, 공통 메시지, 내부 확인 모달, 묶음 완료 상세를 제공합니다.
- 주문은 실제 PG 결제 없는 데모입니다.
- 선택은 화면 상태, 장바구니는 DB에 보관합니다. 숨김·단종 상품은 표시하되 주문을 막습니다.
- 주문 직전 요청 키·본문을 sessionStorage에 회원별로 저장합니다. 저장 불가 시 발급 요청하지 않습니다.
- 통신 실패/5xx/401에서는 동일 키·본문을 유지합니다. 새로고침·같은 계정 재로그인 후 같은 요청으로 결과를 확인합니다.
- 다른 계정으로 바뀌면 이전 계정의 주문을 전송하지 않습니다. 완료 상세는 소유권을 검사하는 BE API에서만 조회합니다.
- 실제 서비스 통합, 상품 상세 담기 버튼, 보내는 사람의 주문 목록은 별도 FE 조율 범위입니다.

정식 반영 전 API·ERD 검토, 기존 공통 스타일/메뉴 연결, 모바일·접근성 검토와 운영 DB/배포 확인이 필요합니다.

## 2026-09-11 보완 내용

### 응답이 끊긴 뒤 수량이 다르게 보이는 문제

서버에서 담기가 처리됐지만 응답을 받지 못하면, 화면의 이전 수량을 보고 다시 담을 수 있습니다. 담기·수량 변경·삭제 후 오류가 발생해도 현재 계정과 장바구니를 재조회하도록 보완했습니다. 수량을 합산하는 POST를 자동으로 재전송하지 않습니다.

재조회도 실패하면 결과가 불확실하다는 안내를 표시하고 추가 변경을 막습니다. 별도 새로고침으로 현재 상태를 확인한 뒤 작업을 재개합니다. 주문의 요청 키를 이용한 재시도는 기존 방식대로 유지합니다.

### 다른 계정으로 바뀐 뒤 이전 화면에서 조작하는 문제

장바구니 조작 전과 조회 결과 표시 전에 현재 계정을 확인합니다. 다른 탭에서 계정이 바뀌었다면 이전 상품·수신자·메시지·완료 내역을 비우고 현재 계정으로 다시 열도록 안내합니다. 창 복귀와 페이지 복원 시에도 확인하며, 확인창이 열린 상태에서 다시 조회하면 기존 확인창을 닫고 가격 등을 재확인하도록 합니다.

이는 오래된 화면에서 다른 계정으로 조작하는 것을 방지하는 FE 보완입니다. 사전 확인과 실제 요청 사이의 모든 계정 전환을 원자적으로 보장하는 기능은 아니며, 최종 소유권 검사는 BE가 수행합니다.

### 화면과 검증 범위

- 기존 사이트의 430px 프레임, 폰트, 흰 배경·검정 버튼·초록 강조 색상에 맞췄습니다. 공통 CSS나 기존 페이지는 수정하지 않았습니다.
- 실제 브라우저에서 320px·430px 폭의 상품 표시를 확인했고, 320px의 문서 폭과 스크롤 폭은 동일했습니다. 실제 모바일 기기 검증과 디자인 승인은 별도입니다.
- 장바구니 DOM 계약 테스트: **21건 통과**.
- FE 전체: **44건 중 43건 통과, 기존 공통 DOM 모형 오류 1건 실패**. `tests/page-urls.test.cjs`의 `confirmBtn.addEventListener is not a function`이며, 이번 보완 범위에서 중복 수정하지 않았습니다.
- 최신 develop 통합 후 전체 테스트를 다시 실행해야 합니다. 현재 결과를 최신 develop 또는 운영 검증으로 해석하지 않습니다.
