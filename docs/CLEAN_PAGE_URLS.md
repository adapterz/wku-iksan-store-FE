# 페이지 주소의 .html 공통 처리

## 범위

FE Express 서버에서 페이지 URL을 정리한다. BE API·DB·디자인·HTML 파일명은 변경하지 않는다.

| 요청 주소 | 결과 |
| --- | --- |
| `/product.html?id=76` | 308 → `/product?id=76` |
| `/product?id=76` | `public/product.html` 응답, 주소 유지 |
| `/index.html`, `/index` | 308 → `/` (쿼리 유지) |
| `/cart` | 배포 파일에 `public/cart.html`이 있으면 응답, 없으면 404 |
| `/api/*` | 기존 BE 프록시 처리 유지 |
| CSS·JS·이미지 | 기존 정적 파일 처리 유지 |

이전 `.html` 링크는 계속 동작한다. 주소창은 서버 리다이렉트로 정리되므로 기존 링크를 모두 수정할 필요는 없다. 새로운 링크는 확장자 없는 주소로 작성하는 것이 좋다. 기존 링크는 첫 이동 시 리다이렉트 요청 1회가 추가된다.

## 구현

- `server/page-router.js`: 존재하는 HTML 파일의 이전 주소를 정규화하고 `express.static`의 `extensions: ['html']`로 확장자를 보완한다. 임의 경로를 홈 화면으로 응답하지 않는다.
- `app.js`: API 프록시 이후 공통 페이지 라우터 적용. 테스트를 위한 `createApp` 내보내기를 추가하되 `npm start` 동작은 유지한다.
- `component.js`: 홈·마이페이지·검색 헤더 예외와 메뉴 활성 상태를 확장자 유무와 무관하게 판별한다.
- `brand.js`, `category.js`, `search.js`: 서버 요청 없이 실행되는 `pushState`·`replaceState`에서도 확장자 없는 URL을 사용한다. 기존 히스토리 방식은 유지한다.

서버의 확장자 보완은 [Express 정적 파일 처리](https://expressjs.com/en/4x/api.html#express.static)를 사용한다.

## 팀 작업과 겹치는 범위

PR #65의 HTML·CSS·ranking.js 변경은 이 작업과 겹치지 않는다. develop에 반영된 PR #69와는 `component.js` 파일을 함께 사용하지만, 이번 변경은 페이지 판별 부분이다. 툴팁·디자인은 변경하지 않는다. 병합 전 최신 develop 기준으로 메뉴·툴팁·페이지 이동을 함께 확인한다.

## 검증

`npm test`로 실제 HTTP 요청을 사용하는 URL 처리와 모의 DOM 검증을 실행한다.

- 이전 주소 리다이렉트, 한글 검색어·상품 ID·로그인 redirect 값 보존
- 신규 HTML 파일 자동 인식 및 현재 모든 public HTML 페이지의 응답 원문 일치
- HEAD·POST 동작, 잘못된 경로·없는 페이지·잘못된 인코딩 처리
- 모의 BE 서버를 통한 GET/POST 프록시 경로와 Set-Cookie 전달 유지
- 공통 페이지 판별 및 로그인 복귀 링크 계산

2026-09-08 자동 테스트 23건 통과. 이후 별도 임시 MySQL DB를 사용하는 로컬 프리뷰에서 실제 BE 로그인·세션 유지·상품 조회·로그아웃 후 세션 무효화를 HTTP 요청으로 확인했다. 프리뷰는 공통 페이지 라우터와 실제 BE 라우트를 한 서버에 연결하며, 운영 프록시 구성의 통합 검증을 대체하지 않는다.

작성자는 로컬 상품 화면을 직접 확인했다. 브라우저 자동 조작은 도구 초기화 오류로 실행하지 못했으므로, 로그인 후 화면 복귀·검색·브랜드/카테고리 선택·뒤로가기의 종합 UI 검증과 운영 배포 후 확인은 남아 있다.

## 배포 및 후속 확인

- FE 컨테이너 재빌드·배포가 필요하다. DB 마이그레이션·BE API 수정은 없다.
- Nginx가 HTML을 직접 제공한다면 FE의 Express를 거치는지 서버 담당자와 확인해야 한다. 이번 작업에서는 운영 Nginx를 변경하지 않는다.
- 배포 후 이전 `.html` 링크, 직접 입력·새로고침, 브랜드/카테고리/검색 이동·뒤로가기, 로그인 복귀를 확인한다.
- 308은 영구 리다이렉트이므로 브라우저 캐시가 남을 수 있다. 이후에도 확장자 없는 주소 처리는 유지하는 것을 전제로 한다.
- 로컬에서도 `npm start`로 확인한다. 단순 파일 열기나 별도 정적 서버에서는 이 공통 라우터가 적용되지 않는다.
- 향후 새 페이지가 `history.pushState` 등으로 URL을 직접 변경한다면 해당 코드에는 확장자 없는 URL을 사용한다. 서버에 새 라우트를 등록할 필요는 없다.
